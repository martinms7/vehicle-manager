# Swiftly Vehicle Manager

React UI for viewing and managing vehicles by transit agency. The app supports loading vehicles, adding rows, inline editing, automatic save on deselection, and deleting the selected vehicle.

## Prerequisites

- Node.js 18.14 or newer. Node.js 22 or newer is recommended.
- npm 9 or newer.
- A vehicle API available at `http://localhost:8080/api/v1/vehicles`, or the built-in mock fallback.

## Install

From this directory:

```powershell
npm install
```

## Run

Start the Vite development server:

```powershell
npm run dev
```

Open the URL printed by Vite, normally `http://localhost:5173`.

The selected agency is read from the `id` query parameter. Supported values are `1` for Boston, `2` for NYC, and `3` for Washington, D.C. For example:

```text
http://localhost:5173/?id=2
```

If the API request fails, the API layer returns the matching mock vehicle DTOs.

## Useful Commands

```powershell
npm run build    # Type-check and create a production build
npm run lint     # Run Oxlint
npm test         # Run the Jest test suite
```

## Tech Stack

- React 19 with TypeScript
- Vite for development and production bundling
- React Router for application routing and query parameters
- TanStack React Query for vehicle fetching, caching, and refetching
- Jest 30 with Babel for test execution and TypeScript/JSX transformation
- React Testing Library and user-event for component behavior tests
- jsdom for browser-like test execution
- Oxlint for linting

## Tests

Tests are colocated under `src/__tests__/` and use Jest with a jsdom environment.

The test suite covers:

- `useVehiclesApi`: GET request handling, DTO-to-domain mapping, mock fallback data, DTO request mapping, and POST/PUT/DELETE request construction.
- `Vehicles`: query-parameter agency loading and API integration for add, update, and delete operations.
- `VehicleList`: row selection, disabled unselected inputs, inline editing, automatic save on deselection, add-row defaults, vehicle-type capacity defaults, and deletion.

Run all tests with:

```powershell
npm test -- --runInBand
```

## What To Improve

- Replace timestamp-generated IDs with IDs generated by the backend, as noted in `VehicleList.tsx`.
- Update the URL query parameter to match the selected `agencyId`, as noted in `Vehicles.tsx`.
- Move API and mutation endpoint configuration into environment variables instead of hard-coded localhost URLs to help with deployment to different environments and testing
  - This would include a config for setting the api port
- Add a clear API error state for failed create, update, and delete operations.
- Add tests for API errors, and perhaps cache perhaps after state changes.
- Implement Users and possibly RBAC so users only have access to their own Agency and their actions (like Add, Delete, Update) are permissioned
- Consider refactoring to an explicit Save function (Pro: Easier state management and less traffic to DB -- Con: Users changing multiple records over time may lose all changes if they forget to hit Save. Also have to repeatedly click Save button)
- Improve UI to allow for multiselect for Deletes
- Improve UI to trigger single field edit on click while maintaining a disabled state for other rows

## AI Tools Used

GitHub Copilot was used in VS Code to:

- Scaffold and refine the `VehicleList` component and its interaction state.
- Diagnose React render loops, API response-shape issues, and Jest environment problems.
- Create and update Jest, Babel, and React testing configuration.
- Generate and adjust unit tests while validating them against the implementation.
- Help draft this project documentation.

All generated changes were reviewed against the local source, diagnostics, and test results. The AI-assisted workflow did not replace local validation or application-level review. Most refinements were done by hand, including removing instances of useEffect for better state management.
